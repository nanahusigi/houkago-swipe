放課後スワイプ
決まったことの全記録

高校生が放課後に飯へ行くまでの、言い出す役を引き受けるアプリ。ここまでの議論で決まったこと、却下したこと、まだ決まっていないことを全部並べてあります。

デモを触る

01これは何か

岡崎の高校生が、放課後に誰かと飯に行くまでを成立させるアプリ。店を探すアプリではありません。

提供価値

決定の責任と、誘う責任を引き受ける

「どこでもいい」は無関心ではなく、決定の責任を取りたくないということ。自分が決めた店がハズレだと気まずいから、みんな譲り合って5分溶ける。

同じように「一緒に行こう」と言い出すのも、断られるリスクを言い出した側が全部背負う行為。だから誘われない。

このアプリが引き受けるのは店の情報ではなく、この2つの責任です。

だから機能の採否は一本の基準で決まります。「決定と誘いの責任を軽くするか?」 イエスなら作る、ノーなら作らない。

02ターゲット

項目決定
エリア岡崎（学校最寄り〜岡崎駅の徒歩圏。まず30〜50軒）
ユーザー高校生
広告主大学 / 専門学校 / 予備校・塾 / 自動車学校 / バイト求人

ターゲットは 高校生 → 中学生 → 高校生 と動いた末に確定。中学生に降ろした理由は「岡崎周辺に大学が少ないから広告主を私立高校にする→ならターゲットは中学生」でしたが、この前提が誤りでした。

大学の商圏は電車1時間圏で、近所にある必要がない。名古屋の大学・専門学校は普通に岡崎の高校生を採りに来ます。高校生向けの広告主はむしろ厚い。
そのうえ高校生に戻すと、親の承認なしにアプリを入れられる／12歳が混ざる問題が消える／バイト代があるので外食する金がある／電車で複数エリアに行けるので店が枯れにくい、と他の懸念もまとめて軽くなります。

誰と行くための機能か

  • 他校の友達（価値が一番濃い）— 中学の友達が別々の高校に散り、時程も部活も違うのでいつ空いてるか分からない
  • 同じ学校の友達も対象 — クラスが違えば動きは別だし、一度家に帰れば仕切り直しになる

03毎日どう使われるか

  1. 通知が1本届く —「今日、外で食う？」
    「暇？」ではないのが肝。質問に意思が入るので、マッチした時点で両者とも外食する気がある状態になる。
  2. 昼 / 放課後 / 夜 のどれかを1タップ
    押さない＝表明なし。押した人同士だけがマッチする。
  3. 合う友達がいたら、両方に同時に届く
    お互い宣言済みなので、言い出す役がいない。断られる余地もない。
  4. 今日の3枚をスワイプ
    カタログ全部ではなく、その日の手札だけ。10秒で終わる。
  5. 今日の1軒が出る
    何があっても必ず1軒。ゼロ件は出さない。
マッチしなかった日

「今日の放課後、友達の2人が外で食う予定」と人数だけ匿名で出す。名前は出さないし、名指しで誘う画面も作らない。押したのに誰も来なかった、という体験を発生させないため。

04主要な設計判断

決めたこと理由
質問は「暇？」ではなく「今日、外で食う？」暇なだけでは飯の気分か分からず、結局「飯行く?」と言い出す役が残る。質問を変えると時間の表明そのものに意思が入る
時間枠は昼/放課後/夜の3つ15〜22時は広すぎ、部活の前後で全く違う。粗すぎると「放課後と言ったのに20時じゃん」で一度に信用を失う。昼枠はテスト期間に効く
マッチは時間が一次、店が二次両方一致を条件にすると成立率が激減して通知が飛ばない。時間さえ合えば店は後から決まればいい
押さない＝表明なしデフォルトを「暇」にすると、行く気のない人がマッチして断ることになり「断られない誘い」の原則が壊れる
相手の予定は見せない見えると「こっちから誘う」が復活して、消したはずの摩擦が戻る。マッチ時に双方へ同時通知のみ
必ず1軒返す「決定を売る」のに決まらないのは自己矛盾。全部パスしても一番安い店を出す
毎日は3枚だけカタログを全部めくらせると在庫が数日で尽きる。同じ30軒でも手札が毎日変われば尽きない
友達グラフは閉じるQR・招待で対面で交換した相手のみ。見知らぬ相手へのメッセージ機能なし、プロフィール外部公開なし。未成年なので出会い系サイト規制法・愛知県青少年保護育成条例の射程に入れない
「みんなで決める」はその場限りの部屋永続グループは作る手間・誰を入れるかの気まずさ・放置される問題を持ち込む。4桁コードで立てて、終わったら消える
グループの決定は多数決全員一致を条件にすると3人以上でゼロ件になる。同点は安い方でタイブレーク

05収益モデル

飲食店からは取りません。店データはユーザーを集めるための餌で、売り物は集まった高校生への広告在庫です。個人店の広告予算は月1〜3万円でゼロの店も多く、何百軒から集めるには営業部隊が要って割に合わないため。

調べて分かった相場
  • 塾ポータル「ジュクサガス」は入塾1人につき3〜5万円の完全成果報酬プランがある
  • 紹介経由の体験申込は入塾率70〜80%、広告経由は50%前後
  • 折込チラシの反応率は0.01〜0.05%（1万枚で1〜5件）
  • LINE広告の友だち追加は200〜400円、体験申込のCPAは5,000円前後の例

意味するところ：「第三者の媒体に成果報酬を払う」のは既に業界慣行で、売るものに前例価格がある。そして紹介の数字は、友達マッチング機能が構造的に「紹介」そのものであることの裏付けになります。

「通知1本にすると広告が出せなくなるのでは」への答え

正しい指摘ですが、モデルを壊すのではなくより良い方へ強制します。

  • 1000人×1日1通知＝月3万インプレッション。表示回数で売れば月数千円で話にならない
  • だが成果で売れば、そこから10人がオープンキャンパスに申し込むだけで数十万円になる
  • 通知は最高の広告枠。スクロールで飛ばされない。1日1通、全員が必ず見る枠は希少
  • 在庫の本体は「みんなで決める」。複数人が数分間同時に使い、同じ広告をその場で話題にする

06店の写真をどう集めるか

自分で全部撮るのはコストが高すぎて更新も続かない。かといってスクレイピングは著作権侵害、AI生成画像は虚偽表示。答えは段階を分けることです。

  1. 当面は写真を使わない — デモは絵文字とテキストだけで成立している。「豚骨・こってり・¥700・替玉無料」で判断できるし、むしろ速い
  2. 種の30〜50軒は「撮る」のではなく「もらう」 — 店はSNS用の写真を既に持っている。無料掲載を条件にもらえば、その時点で許諾も取れる。LINE公式アカウントに送ってもらうだけでいい
  3. 拡大後はユーザーが撮る — 更新問題が構造的に消える。閉店も値上げもユーザーが先に気づく
ユーザーにどう撮らせるか

「撮らせる」必要はありません。もう撮っています。高校生はストーリー用に飯の写真を既に撮っている。設計すべきは撮影の動機づけではなく、撮った直後に1タップで渡せる導線です。

行った日の夜に通知 →「今日◯◯行った? 写真ある?」→ カメラロールの直近を選んで送るだけ。「撮ってきて」ではなく「もう撮ったやつをちょうだい」。

報酬はその店で使えるクーポン。原資を店に持たせるので持ち出しゼロ、現金でないので資金決済法の議論にも入らず、次の来店に直結するので店にとっての価値も高い。採用された1枚だけに出す。

ただし写真をソーシャルの燃料にはしません。投稿者側のメリットがほとんどないからです（下記08参照）。写真は実利で細く集めるものと割り切ります。

チェーン店と個人店

  • スワイプカードの代表写真は全店1枚。土俵を完全に平等にする
  • 詳細画面では個人店だけ複数枚持てる。タップして深掘りしたときだけ個人店が有利になる
  • チェーンは本部承認が要るのでクーポンが通らない。代わりに枚数を集めない
  • 撮影の規格は強制しない（どう撮ろうか迷う時間や楽しみが消えると、そもそも誰も撮らなくなる）。代わりにアップロード後に自動で正方形トリミング＋明るさ補正して、並んだときの見た目だけ揃える
  • 「この店はまだ写真がありません／採用確率が高い」と見せて空白を埋めさせる。スワイプとは別の写真ミッション一覧に置き、スワイプ＝飯を決める場所／ミッション＝稼ぐ場所と役割を分ける

07おすすめの作り方

最初はAIにしません。AIにすると必ず悪くなります。データが少ないうちは学習が効かず、店が30軒では当てる余地も小さく、何よりなぜその店が出たか説明できなくなるから。決定の責任を引き受けるのが売りなのに、理由を言えないのは致命的です。

段階やり方
初期ルールベース。6軸（ガッツリ／甘い／映え／安さ／長居／シェア）のスコアを掛け算して並べる。計算は自動、理由も言える
写真が増えたらタグ付けだけAI。写真からジャンル・価格帯・ボリューム・映えを自動判定。ここは本当にAIが強い
数百人規模から協調フィルタリング（好みが似た人が行った店）。人が少ないうちは動かない

好みは1層ではなく3層ある

  • 変わらない好み（ラーメンが好き、甘いものは食べない）— スワイプの累積で取れる
  • 今日の状態（金がない、時間がない、昨日ラーメン食べた）— スワイプでは永遠に取れない
  • 誰と行くか — 一人の時とゆうとと行く時では選ぶ店が違う

2層目の取り方：聞かずに行動から取る。一番強い信号は直近に何を食べたか（昨日ラーメンなら今日は出にくくする＝飽きを計算に入れる）。次に強いのが3枚をどう扱ったかで、3枚とも見送ったら「今日はズレている」合図なのでその場で1回だけ引き直す。引き直しの時だけ「今日は? 安く／早く／がっつり」を聞けば、毎日聞く重さが出ません。

コールドスタートをどう抜けるか

好みデータがゼロでも初日から価値が出ます。「ゆうとも今日の放課後に外で食う」の成立に好みは1ミリも要らないからです。推薦が本体ではないので、このアプリはコールドスタート問題を構造的に回避できます。

  • 長いオンボーディングは作らない。3枚から始めて毎日3枚ずつ貯まれば、1週間で21枚。初回10分より多く、しかも離脱しない
  • 登録時に「行ったことある店を3つ選んで」だけ — 10秒で終わり、知っている店なので迷わず、スワイプ20回分の情報が入る
  • 招待経由の人には行動範囲（同じ学校・同じ駅＝行ける店の集合）を引き継ぐ。※好みは引き継がない。友達だから好みが似ているというのは成り立たないし、そもそも好みが違うからマッチング機能が要る

08検討して却下した案

案判定理由
飲食店から広告料を取る却下高校生が行くのはチェーンが多く、チェーンは地域単位で広告を買わない。個人店の予算も小さすぎる
金を払った店を上位に出す条件付き露出頻度に金が効くのはOK。ただし好み適合を金で飛び越えさせない。それをやると好みデータが無価値になる
PayPayポイントで写真を買う却下資金決済法（前払式支払手段・為替取引）の議論に入り、個人が軽く始められない。原資が先に出ていく
撮影をアプリ内カメラで規格化却下どう撮ろうか迷う時間と楽しみが消えると、そもそも投稿されない。表示側の自動補正で代替
チェーン店には写真を載せない却下載せる。ただし代表1枚のみ
相互性ルール（出さないと友達の投稿が見られない）撤回成立条件は「見たいものがあること」。友達の飯写真は見たくない。BeRealが成立するのは対象が人だから
スワイプをオンボーディングに限定し、以降は1軒出るだけ撤回開いて1軒出て終わりでは開く理由がない。1軒だけ渡されると押し付けになる。「毎日3枚」に修正
世の中の飯を大量にスワイプさせて好みを取る却下岡崎で食べられない店の好みは30軒にマッピングできない。全国の写真の権利問題も発生。何よりDL直後の離脱要因
飯でマッチしたら相手の予定が見える却下見えると「こっちから誘う」が復活する
飯しか流れてこないInstagram保留発見に戻る案で、決定を売る方向と逆。近所の飯動画が流れるだけならInstagramで足りる
動画（リール型）の左右スワイプ将来体験は面白いが動画のコストは写真の10倍。写真で始めて密度ができてから

09外部からの批判と、それへの答え

初めて第三者（小倉さん）に説明した結果は、かなり批判的でした。

「ただのマッチングアプリやん」「ご飯を口実にマッチングするってことだら」
「誰が使うだ笑」「そこまで便利じゃないし」
「別にスクショしてラインで送ってこいこって」
「遊んでる時とかの話しちゃう」
「その好みがどんくらい絞られてるかによるだろ」

批判答え
LINEでスクショ送れば足りる決定的な差は誘う側のコスト。LINEのスクショは断られるリスクを送り手が全部背負う。アプリの通知は両方が既に宣言している時にしか出ない＝断られない誘いしか発生しない。既存手段では再現不可能
遊んでる時に話しちゃう高校生は電車通学で放課後バラバラに解散するので、一緒にいる時間がそもそも短い。加えて「みんなで決める」モードで一緒にいる場面を最大の利用シーンに反転させる
好みがどれだけ絞れるかによる正しい。だから絞らなくていい形にする。「知らない店を教える」から「今日の1軒を決める」へ。全部知っていても今日どれかは決まっていないので、在庫がなくても価値が出る
ただのマッチングアプリやん人と人ではなく人と店。ただし初見でそう誤解された事実は重い。説明順を固定する（①店を選ぶアプリ ②好みが出る ③今日の1軒が決まる ④おまけで友達と一致したら教える）。名前に「マッチング」を使わない
店側が金払ってまでやるものにならない店から取らないので前提が違う。営業時に先に言えばこの批判は出ない
反省点：「どうやっておすすめ出すねん」に「ai」としか答えられず「頭使え」と返された。具体的な答え（6軸に分解して未スワイプの店に当てる）とデモを既に持っているのに出せていなかった。次は最初にデモを触らせる。

10まだ解けていないこと

  • 毎日押してもらえるか。この設計は「今日、外で食う？」に毎日答えてもらえないと死ぬ。ただしBeRealが失速したのは義務化が重かったからなので、押さない日にペナルティを作らない（押さなければただ静か）
  • そもそも高校生は週に何回外食するのか。「今日どこ行く」の発生回数が週1未満なら、どれだけ作り込んでも開かれない
  • 実績ゼロの新媒体に広告費を出してもらえるか。相場は分かったが、出稿の意思そのものは未検証
  • 3枚が少なすぎないか。引き直しを入れた状態で触ってみないと判断できない
  • 今年やるか、来年やるか。大学生に上げれば未成年の制約が全部消えて広告主も厚くなるが、岡崎に大学がないので実行できない。今年なら高校生・岡崎、来年なら大学生・進学先

11次にやること

原則：先に広告主を押さえてから、ユーザーを集める。逆にすると死ぬ。

  1. Phase 1 — 塾3件＋高校2校に聞く（0円）
    「中学生・高校生に直接届く媒体があったら出稿するか。今どこに広告費を使っているか。生徒1人を獲得するのに実際いくら払っているか」。作る前に聞く。デモをそのまま見せる。塾は教室長がその場で答えられるので先に回る
  2. Phase 0 — 高校生15人に聞く（0円）
    週何回・誰と・どこで・いくら／放課後どこで解散するか／「どこ行く」を決めるのに何分かかるか／誘うのをためらった経験があるか。ここでターゲットを確定させ、以降は動かさない
  3. Phase 2 — アプリを作らずに検証（2週間・0円）
    LINEグループで10人に週1回「今週の3軒」を投げ、手で集計し、一致したら手で通知する。「LINEで直接誘った回数」と「通知経由で実際に行った回数」を分けて数える。前者が多ければこの機能は負け
  4. Phase 3 — 条件付き内諾を取ってから作る
    「◯人集まったら出稿する」を1件でも取る。取れてから開発。法務確認はこの直前
撤退ライン（着手前に確定させる）
  • 高校生の外食が週1回未満 → 「今日の1軒」に価値が出ないので設計から見直す
  • 塾3件＋高校2校の5件中1件も「予算がある」と言わない → 媒体そのものを見直す
  • 手動運用2週間で「実際に友達と行った」が2件出ない → 友達機能の設計を変える

やってから考えると、人は必ず「いける」と判断します。撤退ラインは着手前にしか書けません。

12参考：whooはどう広まったか

Zenly終了という空白を突いた位置共有アプリ。3ヶ月で1000万DL、ユーザーの8割が中高生。

  • ゼロから始めていない — 前作の匿名質問アプリ「Ninjar」で約300万ユーザーを保有し、そこから毎日100件のDMで「次を作って」と要望が来ていた
  • 約1.5ヶ月で作って公開。Zenly終了の1ヶ月半前に出して待っていた
  • 公開3日前にテストユーザーへ予告 → 公開直後に一斉招待 → 30分後からアクティブが倍々
  • 最大の拡散経路はInstagramのストーリー（中高生が最も見る場所）。海外はTikTok
  • 使う理由の1位は「友達が使っているから」45.9%
  • プライバシー懸念を解消する戦略は語られていない。懸念は説得で消えたのではなく「みんな使ってる」に上回られただけ
ここから借りるもの：懸念を言葉で潰そうとせず、局所的に「みんな使ってる」状態を作る（1校1学年に学年LINEで一斉配布＝面で入れる）。ストーリーを設計の前提にする——「今日の1軒」の結果をストーリーに貼れる縦長画像で出せば、招待リンクが自然に回る。whooの300万人の代わりになるのは手が届く自分の学校の300人。
